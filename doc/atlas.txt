1. INTRODUCTION                              *atlas* *atlas.nvim* *atlas-introduction*

Atlas manages GitLab merge requests and issues from inside Neovim.

==============================================================================
2. INSTALLATION                                            *atlas-installation*

With lazy.nvim:
>lua
  {
    "emrearmagan/atlas.nvim",
    dependencies = {
      "nvim-tree/nvim-web-devicons",              -- optional, recommended
      "MeanderingProgrammer/render-markdown.nvim", -- optional, recommended
      "esmuellert/codediff.nvim",                  -- optional, PR diffs
      "sindrets/diffview.nvim", -- optional; or "dlyongemallo/diffview-plus.nvim"
    },
    -- See |atlas-configuration|.
    opts = {},
  }
<
With vim.pack (Neovim 0.12+):
>lua
  vim.pack.add({
    "https://github.com/emrearmagan/atlas.nvim",
  })

  -- See |atlas-configuration|.
  require("atlas").setup({})
<

------------------------------------------------------------------------------
REQUIREMENTS                                               *atlas-requirements*

  - Neovim 0.10+
  - `git` and `curl` on `$PATH`
  - For GitLab: REST API v4 and a Personal Access Token with the `api` scope

Run `:checkhealth atlas` after configuring providers to see what's wired
up and what's missing.

3. CONFIGURATION                                          *atlas-configuration*

>lua
  require("atlas").setup({
    ui = {
      -- Show the Atlas statusline.
      statusline = true,
      -- "auto", "default", "snacks", or "fzf-lua".
      picker = "auto",
      -- Make the main Atlas dashboard a listed buffer (default: true).
      listed_buffer = true,
    },

    providers = {
      ---@type AtlasGitLabConfig
      gitlab = {
        base_url = "https://gitlab.com",
        -- Personal Access Token with `api` scope:
        -- https://docs.gitlab.com/ee/user/profile/personal_access_tokens.html
        token = vim.env.GITLAB_TOKEN,
        cache_ttl = 300, -- Set to 0 to disable caching.
      },
    },

    -- See |atlas-pulls-configuration|.
    pulls = { },
    -- See |atlas-issues-configuration|.
    issues = { },
  })
<

CUSTOM ACTIONS                                    *atlas-custom-actions*
                       *atlas-pulls-custom-actions* *atlas-issues-custom-actions*

Add project-specific actions to pull requests and issues. Custom actions
receive the current item and provider context, making it possible to call
local scripts, open repositories in tmux, copy branch names, or connect Atlas
to your own tooling. They appear in the action menu (default `A`).

>lua
  pulls = {
    repo_config = {
      paths = {
        ["your-workspace/*"] = "~/code/repos/*",
      },
      settings = {},
    },
    custom_actions = {
      {
        id = "show_repo_status",
        label = "Show repository status",
        confirmation = true,
        ---@param pr PullRequest
        ---@param ctx AtlasPullsCustomActionContext
        ---@param done fun(ok: boolean|nil, message: string|nil)
        run = function(_, ctx, done)
          if not ctx.repo_path then
            done(false, "No repo path")
            return
          end

          local output = ctx.output("Repository status")
          output:write("Checking " .. ctx.repo_path)
          output:run({ "git", "status", "--short" }, function(code)
            if code ~= 0 then
              done(false, "Failed to read repository status")
              return
            end
            done(true, "Repository status loaded")
          end, {
            cwd = ctx.repo_path,
          })
        end,
      },
    },
  },
  issues = {
    custom_actions = {
      {
        id = "copy_branch_name",
        label = "Copy branch name",
        ---@param issue Issue
        ---@param ctx AtlasIssuesCustomActionContext
        ---@param done fun(ok: boolean|nil, message: string|nil)
        run = function(issue, ctx, done)
          local branch = string.format("%s/%s", issue.key, issue.title:lower():gsub("%s+", "-"))
          vim.fn.setreg("+", branch)
          done(true, "Copied: " .. branch)
        end,
      },
    },
  }
<

Use `ctx.output(title)` to show output from a custom action:
>lua
  output:write("Loading...")
  output:run(cmd, on_exit, { cwd = "/repo" })
<

==============================================================================
4. COMMANDS                                                    *atlas-commands*

                                                                      *:Atlas*
:Atlas
        Pick an Atlas command.

:Atlas pulls
:Atlas issues
        Open the GitLab pulls or issues dashboard.

:Atlas review [pull-request-url]
        Infer the repository from the current Git remote, pick an open or
        draft merge request, and open its diff. With a URL, open that merge
        request directly.

:Atlas diff [target]
        Open a Git range (`base...head`) or pull-request URL in native
        AtlasDiff. Without a target, Atlas prompts for one.

:Atlas create [pr|issue]
        Start the pull-request or issue creation flow. Without an argument,
        Atlas asks which one to create.

:Atlas search
        Search GitLab pull requests and issues.

:Atlas open [target|.]
        Open a GitLab URL. A PR/issue number is resolved in the current Git
        repository. Use `.` to open the current repository. Without a
        target, Atlas prompts for one.

:Atlas clear [cache]
        Clear all Atlas data, or only cached data and cloned repositories.

:Atlas logs
        Toggle the Atlas log buffer.

                                                                   *:AtlasDiff*
:AtlasDiff <target>
        Open a Git range (`base...head`) or pull-request URL directly in
        native AtlasDiff.

5. PULLS                                                          *atlas-pulls*

Two-pane layout: PRs grouped by view on the left, detail tabs (overview,
conversation, review, and commits) on the right.

Atlas supports configurable views, comments and review threads,
build and merge checks, commits and diffstats, notifications, and pull
request actions, alongside the repository overview, branches, and tags.

Shared provider authentication and endpoints are configured in
|atlas-configuration|.

PULLS CONFIGURATION                              *atlas-pulls-configuration*

Shared config that applies to the pulls provider:
>lua
  require("atlas").setup({
    pulls = {
      default_merge_method = "merge", -- "merge" or "squash"
      default_delete_branch = false,
      git_transport = "https", -- "https" or "ssh" for Atlas-managed Git remotes.
      -- Replaces the built-in Conventional Comments templates.
      comment_templates = {
        insert_mode = true, -- enter Insert mode after applying a template
        items = {
          { label = "Suggestion", text = "suggestion: " },
          { label = "Issue", text = "issue: " },
          { label = "Nitpick", text = "nitpick: " },
        },
      },
      diff = {
        -- Any command that accepts explicit <base>...<head> Git revisions.
        open_cmd = "AtlasDiff", -- default; e.g. "DiffviewOpen" or "CodeDiff"
        show_review_panel = false, -- set true to show the review panel initially
        comment_display = "virtual_lines", -- or compact "virtual_text" hints
        review_panel = {
          height = 10,
        },

        -- AtlasDiff options; external viewers use their own configuration.
        layout = "inline", -- "inline" or "side-by-side"
        compact = true, -- initially show hunks plus surrounding context
        compact_context_lines = 3, -- context lines around hunks in compact mode
        explorer = {
          grouped = true, -- group changed files by directory
          hidden = false,
          show_commits = false, -- set true to show commits below changed files initially
          width = 40,
          initial_focus = "explorer", -- "explorer" or "diff"
          preview = false, -- show a file when the explorer cursor moves onto it
          ignore = { ".git/**", ".jj/**" },
        },
      },
      repo_config = {
        -- Map `workspace/repo` -> local path for checkout / diffs / actions.
        paths = {
          ["your-workspace/*"]    = "~/code/repos/*",
          ["your-workspace/atlas"] = "~/code/atlas",
        },
        settings = {
          ["your-workspace/atlas"] = {
            -- Optional; these are the default values.
            readme      = "README.md",
            pr_template = ".gitlab/merge_request_templates/Default.md",
          },
        },
      },
      custom_actions = {}, -- see |atlas-pulls-custom-actions|
    },
  })
<

------------------------------------------------------------------------------
GITLAB PULLS                                              *atlas-pulls-gitlab*

Auth uses a Personal Access Token with the `api` scope. Set
`providers.gitlab.base_url` to `https://gitlab.com` for the SaaS or your
self-hosted URL. Views can be scoped to assigned/created/all, to a single
project, or to a whole group.

>lua
  pulls = {
    ---@type AtlasGitLabPullsConfig
    gitlab = {
      views = {
        { name = "Assigned",  key = "1", layout = "grouped", -- "compact", "grouped", or "plain"
          scope = "assigned_to_me" },
        { name = "Reviewing", key = "3", scope = "all",
          extra_params = { reviewer_id = "Me" } },
        -- One project:
        { name = "GitLab",    key = "G", project = "gitlab-org/gitlab" },
        -- All projects in a group:
        { name = "GitLab Org", key = "O", group = "gitlab-org" },
      },
    },
  }
<
`extra_params` is passed through to the MR list endpoint. Use it for
anything not covered by the explicit view fields.

REVIEW PULL REQUESTS                         *atlas-review-pull-requests*
                                                     *atlas-pulls-review*

Run `:Atlas review` inside a Git repository to pick an open or draft pull
request, or pass a pull-request URL directly. You can also press the
configured `pulls.open_diff` key (`gd` by default) on a pull request.

  - See pending, resolved, and outdated GitLab threads at their diff
    locations.
  - Add inline or file-level comments and suggestions; reply to, edit, delete,
    resolve, or reopen threads.
  - Submit pending comments with an optional review summary, approve, or
    request changes.
  - Merge pull requests using the methods supported by GitLab.
  - Review GitLab tasks alongside their comments.
  - Browse comments and tasks in the review panel.
  - Mark files reviewed in AtlasDiff.

CodeDiff, sindrets/diffview.nvim, and dlyongemallo/diffview-plus.nvim can
display Atlas comment and task overlays, but their integrations rely on
plugin internals and may break after upstream changes.

------------------------------------------------------------------------------
CREATE PULL REQUESTS                         *atlas-create-pull-requests*
                                                    *atlas-pulls-create*

`:Atlas create pr` opens the pull request form for the current branch. The
newest commit supplies the title. Atlas first reads the configured
`pr_template`, or `.gitlab/merge_request_templates/Default.md` by default.

Without a template, Atlas groups conventional commits into sections,
recognizes leading issue keys such as `[ISSUE-123]`, links commit hashes and
issue references, collects references under Related, and appends the
diffstat. If no commits use a conventional prefix, it uses a linked plain
commit list instead.

Edit the title and description, choose the target branch and reviewers, set
the draft state, or preview commits and diffstat before submitting.

6. ISSUES                                                        *atlas-issues*

Same layout as |atlas-pulls|: list on the left, detail tabs (overview,
conversation, activity) on the right.

Atlas supports configurable views, comments, provider fields and
actions, notifications, custom actions, and issue creation.

Shared provider authentication and endpoints are configured in
|atlas-configuration|.

ISSUES CONFIGURATION                            *atlas-issues-configuration*

Shared config that applies to the issues provider:
>lua
  issues = {
    max_results = 100,
    with_relationships = true, -- fetch parent/subissue relationships
    custom_actions = {}, -- see |atlas-issues-custom-actions|
  }
<

------------------------------------------------------------------------------
GITLAB ISSUES                                            *atlas-issues-gitlab*

Same shared `providers.gitlab` auth as |atlas-pulls-gitlab|. Views take a `scope`
(`assigned_to_me`, `created_by_me`, `all`) and a `state` (`opened`,
`closed`). Anything else goes through `extra_params`.

>lua
  issues = {
    ---@type AtlasGitLabIssuesConfig
    gitlab = {
      views = {
        { name = "Assigned", key = "1",
          scope = "assigned_to_me", state = "opened" },
        { name = "Created",  key = "2",
          scope = "created_by_me", state = "opened" },
        { name = "All open", key = "3",
          scope = "all", state = "opened",
          extra_params = { ["not[labels]"] = "wontfix" } },
      },
    },
  }
<

------------------------------------------------------------------------------
CREATE ISSUES                                      *atlas-create-issues*
                                                    *atlas-issues-create*

`:Atlas create issue` opens the creation flow for GitLab issues in the
current repository. The form supports Markdown descriptions and fields such
as labels, assignees, and milestones.

Atlas can apply a saved Markdown template or save the current description as
a new one. Templates are stored under Neovim's data directory.

==============================================================================
7. EVENTS                                                        *atlas-events*

Atlas emits these `User` events after setup or cleanup completes:

  AtlasUIClosed
      The main pulls/issues dashboard closed.

  AtlasDiffOpened, AtlasDiffClosed
      The native AtlasDiff view opened or closed.

  AtlasReviewAttached, AtlasReviewDetached
      Atlas review overlays attached to or detached from AtlasDiff, CodeDiff,
      or Diffview.

8. KEYMAPS                                                      *atlas-keymaps*

Defaults live under `keymaps` in `setup()`. Each entry accepts:
  - a string -> single key
  - a list of strings -> aliases
  - `false` -> disables the action

>lua
  require("atlas").setup({
    keymaps = {
      ui = {
        help                    = "g?",    -- { "g?", "<leader>?" } for aliases
        close                   = "q",
        back                    = "<BS>",
        next_item               = "j",
        previous_item           = "k",
        first_item              = "gg",
        last_item               = "G",
        select                  = "<CR>",
        submit                  = "<C-s>",
        delete                  = "dd",
        comments = {
          add    = { "a", "i" },
          reply  = "c",
          edit   = "e",
          react  = "gr",
        },
        toggle_panel            = "p",
        toggle_fold             = "za",
        toggle_all_folds        = "zA",
        previous_panel_tab      = "<S-Tab>",
        next_panel_tab          = "<Tab>",
        notifications = {
          open      = "N",
          mark_read = "r",
          mark_done = "d",
        },
        toggle_subscription     = "gS",
        refresh                 = "r",
        refresh_view            = "R",
        open_actions            = "A",
        open_in_browser         = "gx",
        copy_id                 = "y",
        copy_url                = "Y",
        show_details            = "K",
        search                  = "?",
        filter                  = "/",
      },
      picker = {
        next_item    = { "<Down>", "<C-n>", "<C-j>" },
        previous_item = { "<Up>", "<C-p>", "<C-k>" },
        select       = { "<CR>", "<C-s>" },
        toggle       = "<Tab>",
        close        = { "q", "<Esc>" },
      },
      issues = {
        transition_issue = "gs",
        change_assignee  = "ga",
        change_reporter  = "gr",
        edit_issue       = "ge",
        create_issue     = "c",
        toggle_description_mode = "m",
      },
      pulls = {
        open_diff              = "gd",
        checkout               = "gc",
        external_help          = "gA", -- Atlas help in external diff viewers
        toggle_repo_panel      = "o",
        toggle_repo_issue_state = "t",
        edit_title             = "T",
        edit_description       = "D",
        review = {
          focus_item            = "gd",
          approve               = "ga",
          request_changes       = "gr",
          submit_review         = "gs",
          add_task              = "<leader>t",
          comment_templates      = "gT",
          find_file              = "<leader>ff",

            find_file             = { "f", "<leader>ff" },

            toggle_layout         = "t",

            previous_hunk         = "[h",
            toggle_review_panel   = "gR",
            toggle_detail_panel   = "gD",
            toggle_comments       = "gH",
            next_comment          = "]c",
            previous_comment      = "[c",
            add_comment           = "c",
            submit_comment        = "C",
            add_suggestion        = "s",
